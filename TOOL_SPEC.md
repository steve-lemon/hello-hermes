# TOOL_SPEC

## Purpose

This repository defines a TypeScript-based Hermes operating loop tool that shares one core implementation across CLI and MCP interfaces.

## Input Contract

```json
{
  "jobType": "demo",
  "targets": ["https://example.com"],
  "options": {}
}
```

Rules:

- `jobType` must be `demo` during the initialization phase.
- `targets` must contain one or more valid URLs.
- `options` must be a JSON object.

## Output Contract

```json
{
  "jobId": "string",
  "status": "ok | partial | failed",
  "summary": "string",
  "startedAt": "ISO datetime",
  "finishedAt": "ISO datetime",
  "counts": {
    "total": 0,
    "success": 0,
    "failed": 0
  },
  "artifacts": [],
  "errors": []
}
```

Rules:

- `jobId` is generated by the core tool.
- `artifacts` must use repository-relative paths.
- `errors` must follow the structured error contract below.

## Error Contract

```json
{
  "code": "AUTH_REQUIRED | CAPTCHA_BLOCKED | RATE_LIMITED | SELECTOR_CHANGED | VALIDATION_ERROR | DESTRUCTIVE_ACTION_BLOCKED | UNKNOWN_ERROR",
  "message": "string",
  "retryable": true,
  "details": {}
}
```

Rules:

- Do not rename existing error codes without updating all consumers and tests.
- Use `VALIDATION_ERROR` for schema mismatches.
- Use `DESTRUCTIVE_ACTION_BLOCKED` when an operation violates the safety policy.

## Retry Policy

- Retry only when `retryable` is `true`.
- Repeated `RATE_LIMITED` results require a stop-and-notify report to Steve.
- `AUTH_REQUIRED`, `CAPTCHA_BLOCKED`, `SELECTOR_CHANGED`, and schema mismatches are not auto-retry conditions.

## Stop-And-Notify Policy

Hermes must stop and notify Steve before continuing when any of the following occurs:

- `AUTH_REQUIRED`
- `CAPTCHA_BLOCKED`
- repeated `RATE_LIMITED`
- `SELECTOR_CHANGED`
- `DESTRUCTIVE_ACTION_BLOCKED`
- payment, deletion, permission, or large-scale change operations
- output schema mismatches
- success rate below 80%

## Artifact Policy

- Store job results in `artifacts/<jobId>.json`.
- Return artifact paths as repository-relative paths.
- Preserve incidents separately under `incidents/`.
- Use `inspect_result` or the saved artifact to verify outcomes.

## Path Policy

- Never commit absolute local paths into the repository.
- Use repository-relative paths or `<PROJECT_ROOT>` placeholders in docs.
- Use `<TOOL_WORKSPACE>` placeholders in Hermes-facing config examples.
- Runtime installers may resolve machine-specific absolute paths outside the repository at execution time.
